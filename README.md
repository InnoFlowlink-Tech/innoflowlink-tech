# InnoFlowlink Tech

React 19 + Vite company website, with an existing separate Express/MongoDB API.
The production origin required by ASTRA_INSTRUCTIONS.md is:
https://innoflowlink-tech.onrender.com/

## Run and verify

Use Node.js 24 LTS (validated with 24.19.0) and npm. From the project root:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm ci --prefix server --ignore-scripts --no-audit --no-fund
npm run build
npm run lint
npm run verify
node --check server/server.js
npm start
```

The standalone frontend starts on port 4173 unless the host supplies PORT. Stop it with Ctrl+C. For frontend development use `npm run dev`. Production metadata and prerendered HTML are generated by `npm run build`, not the development server.

`npm run verify` starts its own short-lived local HTTP server and checks every public page, redirects, internal assets and anchors, metadata, sitemap, JSON-LD, contact fields and 404 handling. It does not send enquiries or access a real admin account.

The original `npm test --prefix server` command is a placeholder that exits with code 1. It is not an implemented backend test suite. See VERIFICATION_REPORT.md for the complete results and limitations.

## Pages and build

Public paths: `/`, `/web-development/`, `/mobile-app-development/`, `/ai-machine-learning/`, `/game-development/`, `/portfolio/`, `/about/`, `/contact/`.

The build creates real `dist/<route>/index.html` files with prerendered React content, one canonical per page and unique metadata. Ordinary anchor links navigate between pages; there is no added client router dependency. React hydrates the markup for the menu, enquiry form and admin portal. Existing homepage anchor destinations and `/#admin` remain available.

Page copy and metadata live in `src/pages.js`. If routes change, update `public/sitemap.xml` at the same time; verification detects drift. The build's temporary server bundle is removed automatically. Ship `dist` as the public directory, never source or the server directory.

The existing Google Analytics ID is unchanged. Page navigation uses document loads and the existing gtag configuration. `generate_lead` is sent only after the contact API responds successfully, without name, email, phone or requirement parameters.

## Configuration and API

Keep existing hosting configuration and environment values. No `.env` file is supplied, read for inspection, created or edited in this task.

- `VITE_API_URL` remains the frontend's **build-time public API origin reference**. It must keep the correct existing production API origin on the frontend host. Rebuild after changes. Never place private credentials in a `VITE_` variable.
- If this reference is absent, the frontend uses same-origin `/api/...` requests instead of the old broken `undefined/api/...` path. This only works when the deployment actually routes `/api/` to the API.
- This archive's included `dist` was built without private deployment configuration. It is suitable for reviewing HTML and layout; rebuild on your existing host with its existing `VITE_API_URL` before production use. The standalone frontend does not proxy the API.
- The backend still references `MONGO_URI`, `RESEND_API_KEY`, `NOTIFY_EMAIL`, `ADMIN_KEY` and `PORT` exactly as before. Preserve those values on the backend host. Do not copy them into frontend source or send them in messages.
- The backend remains `node server.js` when run from `server`. Its API, authentication middleware, schemas and notification behavior are unchanged.

Read DEPLOYMENT.md before release and VERIFICATION_REPORT.md for changed files and remaining checks.
